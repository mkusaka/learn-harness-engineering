# プロンプトの調整

ルートの指示は、考え得るあらゆる操作を列挙するのではなく、作業の枠組みを定めるべきです。

## ルートファイルに残すもの

- リポジトリの目的とスコープ
- 開始手順
- 検証手順
- 議論の余地がない制約
- 必須の状態アーティファクト
- セッション終了時のルール

## ルートファイルから外すもの

- 長い履歴的なエッジケース
- テーマ固有の実装詳細
- コードの近くに置くべきローカルなアーキテクチャメモ
- 1つのサブシステムにしか当てはまらない例

## 作業ルール

ルートファイルは、新しいセッションがすばやく状況を把握できるようにするべきです。過去の失敗を何でもかんでも詰め込んだ状態になったら、詳細はより小さなドキュメントへ分離し、それらへのリンクだけを残してください。
