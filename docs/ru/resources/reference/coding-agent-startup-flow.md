# コーディングエージェントの起動フロー

初期化が完了したら、各セッションの開始時にこれを使ってください。

## 固定の起動テンプレート

1. `pwd` を実行して、リポジトリのルートを確認します。
2. `claude-progress.md` を読みます。
3. `feature_list.json` を読みます。
4. 直近のコミットを確認します: `git log --oneline -5`
5. `./init.sh` を実行します。
6. 基本的な smoke パスまたは end-to-end パスを実行します。
7. 基本の検証が壊れている場合は、まずそれを修正します。
8. 未完了の機能のうち、最も優先度が高いものを選びます。
9. その機能が検証されるか、明確にブロックされるまで、その機能だけに取り組みます。

## この順序が重要な理由

- `pwd` により、誤ったディレクトリで作業してしまうのを防げます。
- 進捗ファイルと機能ファイルは、新しい修正を始める前に永続的な状態を復元します。
- 直近のコミットを見れば、最後に何が変わったのかがわかります。
- `init.sh` は、記憶に頼るのではなく、開始手順を標準化します。
- 基本の検証は、新しい作業が問題を覆い隠す前に、壊れた起動状態を検出します。

## セッション終了時の対応

同じセッションは、次の手順で終了する必要があります:

1. 進捗を記録する
2. 機能の状態を更新する
3. 必要であれば `handoff` を書く
4. 安全な作業をコミットする
5. 再開しやすいきれいな状態を残す
