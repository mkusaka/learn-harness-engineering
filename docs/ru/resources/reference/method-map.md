# メソッドマップ

この表は、コーディングエージェントの長時間タスクでよく起こる失敗モードを、それを最初に解消することが多いアーティファクトまたは運用ルールに対応付けています。

| 失敗モード | 実際にはどう見えるか | 最初の対処 | 補助アーティファクト |
| --- | --- | --- | --- |
| Cold-start confusion | 新しいセッションが、セットアップと状態の再確認に大半の時間を費やしてしまう | リポジトリを記録システムにする | `claude-progress.md` |
| Scope sprawl | エージェントが複数の機能に着手し、どれもきれいに最後まで仕上げない | アクティブなスコープを絞る | `feature_list.json` |
| Premature completion | コード修正のあと、実行可能な証拠が出る前にエージェントが done を宣言する | 完了条件を証拠に紐づける | `clean-state-checklist.md` |
| Fragile startup | 毎回のセッションで、プロジェクトの立ち上げ方を学び直してしまう | セットアップと検証を標準化する | `init.sh` |
| Weak handoff | 次のセッションが、何が検証済みで、何が壊れていて、次に何をすべきかを理解できない | 明示的な handoff で終える | `session-handoff.md` |
| Subjective review | レビュー品質が、好みや記憶に左右される | 出力を固定カテゴリで評価する | `evaluator-rubric.md` |

## 運用原則

観測された失敗モードに直接対処する、最小限のアーティファクトを追加してください。信頼性のあらゆる問題を、1つの巨大な指示ファイルにどんどん文章を足して解決しようとしないでください。
