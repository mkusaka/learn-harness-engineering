# AGENTS.md

このリポジトリは、長期的な作業を前提にしたコーディングエージェント向けです。目的は、単純なコード量を最大化することではありません。次のセッションが迷わず作業を引き継げる状態でリポジトリを保つことです。

## スタート時のワークフロー

コードを書く前に:

1. `pwd` コマンドで作業ディレクトリを確認してください。
2. `claude-progress.md` を読んで、最後に確認された状態と次の手順を把握してください。
3. `feature_list.json` を読んで、未完了の機能のうち最も優先度が高いものを選んでください。
4. 最新のコミットを確認してください: `git log --oneline -5`
5. `./init.sh` を実行してください。
6. 新しい作業を始める前に、必要な smoke もしくは end-to-end の検証を実行してください。

基本の検証がすでに失敗している場合は、最初にそこを直してください。壊れた初期状態の上に新しい機能を重ねないでください。

## 作業ルール

- 一度に 1 つの機能だけに取り組んでください。
- コードを追加しただけで機能完了と見なさないでください。
- ブロッカーのために最小限の補助修正が必要な場合を除き、変更は選んだ機能のスコープ内に収めてください。
- 実装の途中で検証ルールをこっそり変えないでください。
- チャットでの要約より、リポジトリ内に残る永続的な成果物を優先してください。

## 必須成果物

- `feature_list.json`: 機能の状態に関する唯一の正しい情報源
- `claude-progress.md`: セッションログと現在の確認済み状態
- `init.sh`: 標準的な起動および検証手順
- `session-handoff.md`: 大きなセッション向けの、任意の簡潔な引き継ぎメモ

## 完了条件

機能が完了したと見なせるのは、以下をすべて満たしたときだけです。

- 目的の動作が実装されている
- 必要な検証を実際に実行した
- 証拠を `feature_list.json` か `claude-progress.md` に記録した
- リポジトリが標準の起動手順で引き続き再実行可能である

## セッション終了時

セッションを終える前に:

1. `claude-progress.md` を更新してください。
2. `feature_list.json` を更新してください。
3. 未解決のリスクやブロッカーをすべて記録してください。
4. 作業が安全な状態になったら、説明的なメッセージでコミットしてください。
5. 次のセッションがすぐに `./init.sh` を実行できる程度に、リポジトリをきれいな状態に保ってください。
