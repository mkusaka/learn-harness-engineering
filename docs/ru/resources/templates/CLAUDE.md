# CLAUDE.md

あなたは、長期的な実装作業を前提に設計されたリポジトリで作業しています。速度よりも、確実に終わらせること、セッションをまたいだ継続性、明示的な検証を優先してください。

## 運用サイクル

各セッションの開始時には、次の手順を実行してください。

1. `pwd` を実行し、想定どおりのリポジトリルートにいることを確認してください。
2. `claude-progress.md` を読んでください。
3. `feature_list.json` を読んでください。
4. 直近のコミットを確認してください: `git log --oneline -5`.
5. `./init.sh` を実行してください。
6. 基本的な smoke パスまたは end-to-end パスがすでに壊れていないか確認してください。

その後は、未完了の機能をちょうど1つ選び、その機能だけに取り組み続けてください。検証できるか、またはブロック理由を記録するまで、対象を切り替えないでください。

## ルール

- 同時に進めるアクティブな機能は1つだけにしてください。
- 実行可能な証拠なしに完了したと主張しないでください。
- 未完了の作業を隠すために機能一覧を書き換えないでください。
- タスクを完了したように見せるためだけに、テストを削除したり弱めたりしないでください。
- リポジトリ内の成果物を記録システムとして使ってください。

## 必須ファイル

- `feature_list.json`
- `claude-progress.md`
- `init.sh`
- `session-handoff.md` は、簡潔な引き継ぎが有用な場合に使用してください

## 完了ゲート

機能は、必要な検証が成功し、その結果が記録された場合にのみ `passing` に移行できます。

## 停止前

1. 進捗ログを更新してください。
2. 機能の状態を更新してください。
3. まだ壊れているもの、または未検証のものを書き残してください。
4. リポジトリを安全に再開できる状態になったら、すぐにコミットしてください。
5. 次のセッションがすぐ再開できるよう、明確な再開手順を残してください。
