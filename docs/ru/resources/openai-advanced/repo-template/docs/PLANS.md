# PLANS.md

このファイルでは、exec plan をどのように作成し、更新し、完了させ、アーカイブするかを定めます。

## plan が必要な場合

exec plan を作成するのは、作業が次のいずれかに当てはまる場合です。

- 1 回のセッションで終わらない
- 2 つ以上のサブシステムにまたがる
- 検証または展開に関して、非自明なリスクがある
- 未決定の内容に依存しており、それを明確に記録する必要がある

## plan の保存場所

- `docs/exec-plans/active/`: 現在進行中の作業を管理する plan
- `docs/exec-plans/completed/`: 完了した plan を保存し、将来の agent の文脈に残す場所
- `docs/exec-plans/tech-debt-tracker.md`: 保留中の作業と follow-up

## plan の最小セクション

- 目的
- スコープと out-of-scope
- 検証手順
- リスクとブロッカー
- 進捗ログ
- 未決定事項

## 作業ルール

- 1 つのアクティブな plan には、現在の担当ステップが 1 つだけ含まれていなければなりません。
- 作業に合わせて plan を更新してください。静的な文章として扱ってはいけません。
- 実装方針が変わった場合は、その内容を plan に記録してください。
- 完了した plan は `completed/` に移動し、agent が過去の文脈を参照できるようにしてください。
