# FRONTEND.md

このファイルは、エージェントが予測不能に UI パターンを生み出さないようにするための、
フロントエンドに関する安定した期待値を定めます。

## UI の原則

- 新しさよりも、まず分かりやすさを優先します。
- インタラクションの流れは、見つけやすく、やり直しやすいものにします。
- 使い捨ての実装よりも、少数の再利用可能なコンポーネントを優先します。
- アクセシビリティの確認は最後の仕上げではなく、通常の検証の一部として扱います。

## 制約

- デザインシステムやコンポーネントライブラリは `docs/references/` に文書化します。
- 空、読み込み中、成功、失敗、再試行といった、ユーザーに見える重要な状態を固定します。
- 画面遷移やフロー間で、コピー文、キーボード操作、視覚的な階層の一貫性を保ちます。
- UI のバグを修正したら、対応する検証手順を追加または更新します。

## 検証の期待値

- 重要なユーザーシナリオについては、証跡を取得します。
- ブラウザまたはランタイムでの検証手順を、該当する計画に記録します。
- 視覚的な回帰が多い場合は、スクリーンショットや DOM のチェックを標準化します。
