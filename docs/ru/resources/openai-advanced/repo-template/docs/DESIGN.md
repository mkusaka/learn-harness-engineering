# DESIGN.md

このファイルはデザインの入口です。短く保ち、`docs/design-docs/` の
より詳細なファイルへ案内するために使ってください。

## 目的

個別のチャット、スプリント、またはレビュー担当者の記憶を超えて残る、
長期的なプロダクトおよびシステムのデザイン判断を記録します。

## 読むタイミング

- 現在のデザイン方針を把握したいとき
- 新しいパターンを導入しようとしているとき
- どのデザイン判断が確定していて、どれが未解決かを理解したいとき

## 正式なデザイン文書

- `docs/design-docs/index.md`: 承認済み、提案中、廃止済みの文書の索引
- `docs/design-docs/core-beliefs.md`: プロジェクト全体の agent-first の信念

## デザインルール

- デザイン文書は小さく、最新の状態に保ってください。
- 1つの判断領域につき1つの文書を基本にしてください。
- 変更が依存する場合は、計画書や仕様書からデザイン文書へリンクしてください。
- デザインルールが運用上クリティカルになったら、自動化された検証に
  変えるか、`ARCHITECTURE.md` を更新してください。
