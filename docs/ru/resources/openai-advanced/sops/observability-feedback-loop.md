# SOP: 可観測性 Feedback Loop

デバッグが遅々として進まないとき、エージェントが証拠なしに成功を主張し続けるとき、あるいはコードそのものよりも実行時の挙動のほうが観察しづらいときに、この SOP を使ってください。

## 目的

ログ、メトリクス、トレース、実行中の負荷を使ってエージェントにローカルな feedback-loop を与え、コードの静的確認だけでなく実行結果から推論できるようにします。

## 最小構成

- アプリケーションが構造化ログを出力する
- 可能であれば、アプリケーションがメトリクスとトレースを出力する
- ローカルの fan-out または collection 層がある
- ログ、メトリクス、トレースを問い合わせるためのインターフェースがある
- 各変更後に再実行できる、再現可能な負荷またはユーザーシナリオがある

## 実行 SOP

1. 最も重要な golden ランタイムシナリオを特定します。
2. 起動時と重要な処理経路に構造化ログを追加します。
3. 有用な場合は、レイテンシ、失敗数、キュー深度のメトリクスを追加します。
4. 遅い処理や多段のフローには、トレースまたは時間マーカーを追加します。
5. ローカルの dev 環境からこれらのシグナルを問い合わせできるようにします。
6. エージェントに、1つの再現可能な負荷または再起動可能なシナリオを与えます。
7. `request -> correlation -> reasoning -> implementation -> restart -> repeat -> verification` のサイクルを求めます。

## デバッグセッションのチェックリスト

- 何が落ちたか？
- どのシグナルが失敗を証明しているか？
- その失敗はどの層に属するか？
- 修正後に何が変わったか？
- アプリケーションはクリーンに再起動したか？
- 同じ負荷は再起動後も通ったか？

## 完了条件

- エージェントが、実行時の証拠に基づいて失敗モードを説明できる。
- 同じ負荷を各変更後に再起動できる。
- 再起動と再実行が、通常のタスクサイクルの一部になっている。
- 信頼性シグナルが `docs/RELIABILITY.md` に文書化されている。
