# SOP: Chrome DevTools の検証ループ

UI の作業が実際のランタイム相互作用に依存し、コードの検査だけでなく
スクリーンショット、DOM の状態、コンソール出力のほうが重要な場合にこの SOP を使います。

## 目的

UI の検証を、エージェントがシナリオをクリーンな状態にできるまで
実行し続けられる再現可能な相互作用ループに変えます。

## 基本ループ

1. 対象ページまたはアプリケーションのインスタンスを選びます。
2. コンソールの古いノイズを消します。
3. 事前状態を記録します。
4. UI のパスをトリガーします。
5. 相互作用中のランタイムイベントを監視します。
6. 事後状態を記録します。
7. 修正を適用し、必要に応じてアプリケーションを再起動します。
8. 検証を、シナリオがクリーンになるまで繰り返します。

## 必須入力

- 安定した起動コマンド
- 再現可能な UI シナリオ
- DOM、コンソール、またはスクリーンショットを取得する手段
- 何を「クリーン」とみなすかのルール

## 実行手順

1. 対象シナリオをアクティブな実行計画に書き込みます。
2. 成功条件を観測可能な形で定義します。たとえば、テキストが存在する、ボタンが有効、
   エラーが消える、コンソールがクリーン、リクエストが成功する、などです。
3. 相互作用の前に初期状態のスナップショットを取得します。
4. 一度にトリガーするのは1つのパスだけにします。
5. ランタイムイベント、DOM の変化、見えている出力を記録します。
6. シナリオが失敗したら、責任範囲が最小のレイヤーを修正して再起動します。
7. 同じパスを再実行し、事前/事後の証拠を比較します。

## クリーン判定

- 意図した可視状態が存在する
- 予期しないエラーがない
- コンソールのノイズが理解済み、または消去済みである
- 同じパスを再実行しても同じ結果になる

## 更新対象のリポジトリアーティファクト

- アクティブな exec plan
- `docs/RELIABILITY.md`。シナリオが golden path になった場合
- 可視的な挙動が変わった場合は、製品仕様
