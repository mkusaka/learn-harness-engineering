# SOP: Observability Feedback Loop

デバッグが遅い場合、エージェントが証拠なしに成功を主張し続ける場合、または実行時の挙動のほうがコード本体より把握しづらい場合に、この SOP を使います。

## 目的

ログ、メトリクス、トレース、実行可能なワークロードを通じてエージェントにローカルなフィードバックループを与え、コードの確認だけでなく実行結果から判断できるようにします。

## 最小構成

- アプリケーションが構造化ログを出力する
- 可能であればアプリケーションがメトリクスとトレースを出力する
- ローカルの fan-out 層または収集層
- ログ、メトリクス、トレースのクエリインターフェース
- 変更のたびに再実行できる、繰り返し可能なワークロードまたはユーザージャーニー

## 実行 SOP

1. 重要度の高い、基準となる実行時ジャーニーを定義します。
2. 起動処理とクリティカルパスに構造化ログを追加します。
3. 必要に応じて、レイテンシ、失敗件数、キュー深度のメトリクスを追加します。
4. 遅い処理や複数ステップのフローにはトレースやタイミングマーカーを追加します。
5. ローカルの開発環境からこれらのシグナルをクエリできるようにします。
6. エージェントに、再実行可能なワークロードまたはシナリオを1つ与えます。
7. ループを必須にします: query -> correlate -> reason -> implement -> restart ->
   rerun -> verify.

## デバッグセッションのチェックリスト

- 何が失敗したか?
- どのシグナルが失敗を証明しているか?
- どのレイヤーがその失敗を担当しているか?
- 修正後に何が変わったか?
- アプリは正常に再起動したか?
- 同じワークロードは再実行後に通ったか?

## 完了条件

- エージェントが実行時の証拠から失敗モードを説明できる。
- 同じワークロードを各変更後に再実行できる。
- 再起動と再実行が通常のタスクループに含まれている。
- 信頼性シグナルが `docs/RELIABILITY.md` に文書化されている。
