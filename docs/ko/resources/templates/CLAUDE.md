# CLAUDE.md

このファイルは、harness リソースライブラリに含まれるサンプルテンプレートです。実際のプロジェクトにコピーしたうえで、そのプロジェクト固有のコマンドとパスに合わせて修正して使用してください。`AGENTS.md` と構造は同じで、Claude Code の指示スタイルに合わせて整形した版です。

あなたは、長期的な実装作業向けに設計されたリポジトリで作業しています。速度よりも、確実な完了、セッション間の継続性(continuity)、明示的な検証(verification)を優先してください。

## 運用ループ (Operating Loop)

すべてのセッション開始時に:

1. `pwd` を実行して、想定どおりのリポジトリルートにいることを確認します。
2. `claude-progress.md` を読みます。
3. `feature_list.json` を読みます。
4. `git log --oneline -5` で最近のコミット(commit)を確認します。
5. `./init.sh` を実行します。
6. ベースライン(baseline)のスモーク(smoke)経路またはエンドツーエンド(end-to-end)経路が既に壊れていないか確認します。

その後、未完了の機能を1つだけ正確に選び、検証が完了したか、あるいはブロックされていると明示的に文書化するまで、その機能だけを作業してください。

## ルール (Rules)

- 同時に有効にできる機能は1つだけです。
- 実行可能な証拠(evidence)なしに完了を主張しません。
- 未完了の作業を隠すために機能一覧を書き換えません。
- 作業が完了したように見せるために、テストを削除したり弱めたりしません。
- システム・オブ・レコード(system of record)として、リポジトリの成果物(repository artifacts)を使用します。

## 必須ファイル (Required Files)

- `feature_list.json`
- `claude-progress.md`
- `init.sh`
- `session-handoff.md` — 簡潔なハンドオフ(handoff)が有用な場合

## 完了ゲート (Completion Gate)

必要な検証が成功し、その結果が記録された後でのみ、機能を `passing` に移行できます。

## 中断する前に (Before You Stop)

1. 進捗ログ(progress log)を更新します。
2. 機能の状態(feature state)を更新します。
3. まだ壊れているもの、または未検証のものを記録します。
4. リポジトリを再開可能な状態にできたら、コミットします。
5. 次のセッションのために、クリーン(clean)な再開手順を残します。
