# AGENTS.md

このファイルはハーネス(harness)リソースライブラリに含まれるサンプルテンプレートです。実際のプロジェクトにコピーしたあと、プロジェクト固有のコマンドとパスに合わせて修正して使用してください。エージェント(agent)がセッションを開始するときに最初に読むファイルであり、安定した長期作業の土台になります。

このリポジトリは、長期的なコーディングエージェント作業のために設計されています。目的はコード成果物(output)を最大化することではありません。次のセッションが推測なしで続行できるように、リポジトリを整えて残すことが目的です。

## 開始ワークフロー (Startup Workflow)

コードを書く前に:

1. `pwd` で作業ディレクトリを確認します。
2. `claude-progress.md` を読んで、最新の検証(verified)状態と次のステップを確認します。
3. `feature_list.json` を読んで、最も優先度の高い未完了機能を選びます。
4. `git log --oneline -5` で直近のコミット(commit)を確認します。
5. `./init.sh` を実行します。
6. 新しい作業を始める前に、必要なスモーク(smoke)またはエンドツーエンド(end-to-end)検証を実行します。

基準線(baseline)の検証がすでに失敗している場合は、先にそれを修正してください。壊れた開始状態の上に新機能の作業を積み重ねないでください。

## 作業ルール (Working Rules)

- 一度に作業する機能は1つだけにします。
- コードを追加しただけでは、機能完了とは扱いません。
- ブロッカー(blocker)が狭い支援修正を強制しない限り、選択した機能の範囲内で変更を収めます。
- 実装中に検証ルールを黙って変更しません。
- チャットの要約よりも、継続的に残るリポジトリ成果物(durable repo artifacts)を優先します。

## 必須成果物 (Required Artifacts)

- `feature_list.json`: 機能状態の唯一の正本(single source of truth)
- `claude-progress.md`: セッションログと現在の検証状態
- `init.sh`: 標準の開始および検証経路
- `session-handoff.md`: 大規模セッション向けの任意の簡潔な引き継ぎ(handoff)

## 完了条件 (Definition Of Done)

次の条件がすべて満たされたときのみ、機能は完了です。

- 目標動作が実装されている
- 必要な検証が実際に実行されている
- 証拠(evidence)が `feature_list.json` または `claude-progress.md` に記録されている
- リポジトリが標準の開始経路から再起動可能な状態を維持している

## セッション終了 (End Of Session)

セッションを終了する前に:

1. `claude-progress.md` を更新します。
2. `feature_list.json` を更新します。
3. 未解決のリスクまたはブロッカーを記録します。
4. 作業が安全な状態であれば、説明的なメッセージでコミットします。
5. 次のセッションがすぐに `./init.sh` を実行できるよう、リポジトリを十分にクリーン(clean)な状態で残します。
