# コーディングエージェントの起動フロー (Coding Agent Startup Flow)

初期化(initialization)が完了したら、すべてのセッション開始時にこのフローを使ってください。この固定された順序に従えば、エージェント(agent)が状態を再確認するために時間を無駄にせず、すぐに作業へ集中できます。

## 固定の起動テンプレート (Fixed Startup Template)

1. `pwd`を実行して、リポジトリのルートを確認します。
2. `claude-progress.md`を読みます。
3. `feature_list.json`を読みます。
4. `git log --oneline -5`で直近のコミット(commit)を確認します。
5. `./init.sh`を実行します。
6. ベースライン(baseline)のスモーク(smoke)またはエンドツーエンド(end-to-end)の経路を実行します。
7. ベースラインが壊れている場合は、先に修正します。
8. 最優先の未完了機能を選びます。
9. 検証が完了するか、明示的にブロックされるまで、その機能だけを作業します。

## この順序が重要な理由 (Why This Order Matters)

- `pwd`は、誤ったディレクトリで作業してしまうのを防ぎます。
- 進捗ファイルと機能ファイルは、新しい編集を始める前に永続的な状態(durable state)を復元します。
- 直近のコミット(commit)は、最後に何が変更されたかを示します。
- `init.sh`は、記憶に頼るのではなく開始手順を標準化します。
- ベースライン(baseline)の検証は、新しい作業がそれを隠してしまう前に、壊れた開始状態を見つけます。

## セッション終了時のミラー (End-Of-Session Mirror)

同じセッションは、次の順序で終了しなければなりません。

1. 進捗状態を記録する
2. 機能状態を更新する
3. 必要に応じてハンドオフ(handoff)を作成する
4. 安全に作業をコミット(commit)する
5. クリーン(clean)な再起動経路を維持する
