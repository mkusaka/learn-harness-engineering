# PRODUCT_SENSE.md

このファイルには、エージェント(agent)がコードだけでは信頼して推論できない、継続的な製品判断を記します。

product sense の文書は、単なる feature spec を超えて、チームがどの種類の判断をどの優先順位で下すべきかに関する横断的な原則をエージェントに提供します。

- 実現したい job to be done: `[置き換える]`
- 解消したい主要な不満: `[置き換える]`
- 受け入れ品質基準: `[置き換える]`

## 製品ルール

- 機能数よりも、ユーザーから見える信頼性(reliability)を優先する。
- あいまいな動作は、推測してよい権限ではなく、仕様の抜け(spec gap)として扱う。
- 実装によってユーザーが見たり信頼したりするものが変わる場合は、それに一致する仕様を更新する。
- 個別のフローには product spec を使い、横断的な製品優先順位にはこのファイルを使う。

## 禁止パターン

- 隠れた破壊的動作
- ユーザーへのフィードバックがない無音の失敗
- 可視状態に対する不明瞭な真実の源泉
- 1文で説明できない機能
