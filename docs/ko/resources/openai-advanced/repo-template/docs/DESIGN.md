# DESIGN.md

このファイルは設計の入口(design entrypoint)です。簡潔に保ち、`docs/design-docs/` 配下のより詳細なファイルへ誘導するために使ってください。

## 目的

単発のチャット、スプリント、あるいはレビュー担当者の記憶を超えて残すべき、長く有効なプロダクトおよびシステム設計上の決定を記録します。

設計文書(design doc)は、単なるコードコメントや PR 説明とは異なり、決定に至った理由と文脈を長期的に残し、将来のエージェント(agent)と人間が同じ失敗を繰り返さないようにします。

## 読むべき場面

- 現在の設計思想が必要なとき
- 新しいパターンを導入しようとするとき
- どの設計判断が確定済みで、どれがまだ未決定かを把握したいとき

## 規範的な設計文書

- `docs/design-docs/index.md`: 受理済み、提案中、破棄済みの状態を持つ文書の索引
- `docs/design-docs/core-beliefs.md`: プロジェクト全体に共通する agent-first の信条

## 設計ルール

- 設計文書は小さく、現在の状態を保つ。
- 1 つの決定領域につき 1 つの文書を優先する。
- 変更が設計文書に依存する場合は、計画と仕様の中でその設計文書にリンクする。
- 設計ルールが運用上重要になったら、自動化された検査に昇格させるか、`ARCHITECTURE.md` を更新する。
