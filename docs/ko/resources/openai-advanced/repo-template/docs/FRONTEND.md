# FRONTEND.md

このファイルは、安定したフロントエンドの期待値を定義し、agent が予測不能に UI パターンを発明しないようにします。

フロントエンドのポリシー文書は、agent が UI 作業中に場当たり的なパターンを選ばないよう、デザインシステムのルール、アクセシビリティ基準、検証方法をあらかじめ明示する役割を持ちます。

## UI 原則

- 斬新さよりも明快さを優先する。
- インタラクションの流れは、見つけやすく、再開しやすい状態に保つ。
- その場限りのバリエーションより、少数の再利用可能なコンポーネントを優先する。
- アクセシビリティの検査は仕上げ作業ではなく、通常の検証の一部である。

## ガードレール(Guardrail)

- デザインシステムまたはコンポーネントライブラリを `docs/references/` に文書化する。
- 主要なユーザー向け状態を記録する: 空の状態、読み込み中、成功、エラー、再試行。
- コピー文言、キーボード操作、視覚的な階層を、フロー全体で一貫して保つ。
- UI のバグを修正するときは、対応する検証ステップを追加または更新する。

## 検証の期待値

- 重要なユーザージャーニーの証拠を記録する。
- 関連する計画には、ブラウザまたは runtime の検証ステップを記録する。
- visual regression が頻発する場合は、スクリーンショット検査または DOM 検査を標準化する。
