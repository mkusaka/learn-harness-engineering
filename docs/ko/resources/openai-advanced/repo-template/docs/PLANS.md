# PLANS.md

このファイルは、実行計画(`execution plan`)をどのように作成・更新・完了・保管するかを定義します。

実行計画は、単一セッションを超える作業、複数のサブシステムにまたがる変更、あるいは明示された決定事項がある作業を、構造化された形で追跡します。計画をリポジトリに永続化することで、エージェント(`agent`)は過去のコンテキスト(`context`)がなくても作業を引き継げます。

## 計画が必要な場合

次に該当する場合は、実行計画を作成します。

- 1つ以上のセッションにまたがる作業
- 1つ以上のサブシステムを変更する作業
- 重要な検証またはデプロイのリスクを伴う作業
- 記録しておくべき未決定事項がある作業

## 計画の配置場所

- `docs/exec-plans/active/`: 現在の作業を導く計画
- `docs/exec-plans/completed/`: 将来のエージェントのコンテキストのために保管された完了済み計画
- `docs/exec-plans/tech-debt-tracker.md`: 後回しにされた作業とフォローアップ

## 最低限必要な計画セクション

- 目標(`objective`)
- 範囲と範囲外(`scope and out-of-scope`)
- 検証経路(`verification path`)
- リスクとブロッカー(`risks and blockers`)
- 進捗ログ(`progress log`)
- 未決定事項(`open decisions`)

## 運用ルール

- 1つのアクティブな計画には、現在進行中の段階が明確に1つだけ存在しなければなりません。
- 作業が進んだら計画を更新します。静的な文章として扱ってはいけません。
- 決定によって実装方針が変わる場合は、計画に記録します。
- 完了した計画は、エージェントが過去のコンテキストを引き続き参照できるように `completed/` へ移動します。
