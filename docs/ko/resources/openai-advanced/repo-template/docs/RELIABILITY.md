# RELIABILITY.md

このファイルは、システムがどのように健全で、再起動可能であることを証明するかを定義します。

信頼性(reliability)ドキュメントは、エージェント(agent)が機能実装後にシステムをきれいに再起動できるか、またランタイム失敗を診断できるかを確認するために必要な経路とシグナルを提供します。信頼性をガードレールとして定義することで、機能追加によってシステムの安定性が暗黙のうちに低下するのを防ぎます。

- ブートストラップ(Bootstrap): `[コマンド]`
- 検証(Verification): `[コマンド]`
- アプリまたはサービスの起動: `[コマンド]`
- ランタイムのデバッグまたは検査: `[コマンド]`

## 必須ランタイムシグナル

- 起動および重要なフローに関する構造化ログ
- 主要サービスに対するヘルスチェック(health check)
- 可能であれば、遅い経路に関するトレースまたはタイミングデータ
- 回復可能な失敗に対する、ユーザーから見えるエラー状態

## 信頼性ルール

- システムがその後にきれいに再起動できないなら、どの機能も完了したとはいえません。
- ランタイム失敗は、リポジトリ内のローカルシグナルで診断できる必要があります。
- 繰り返し発生する失敗モードが現れたら、そのモードに対するベンチマークまたはガードレールを追加します。
- クリーンアップ(cleanup)は信頼性の一部であり、別個の関心事ではありません。
