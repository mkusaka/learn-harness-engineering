# SOP: Chrome DevTools 検証ループ(Validation Loop)

UI 作業が実際のランタイムでの相互作用に依存しており、コードを確認するだけでは不十分で、スクリーンショット・DOM 状態・コンソール出力のほうが重要なときに、この標準作業手順(SOP)を使用してください。

検証ループ(validation loop)とは、特定の UI ジャーニー(journey)がきれいに完了するまで、BEFORE/AFTER の状態を繰り返し比較しながら問題を絞り込んでいくデバッグサイクルです。

## 目的

UI の有効性検証(validation)を、エージェント(agent)がジャーニーがきれいになるまで繰り返し実行できる、再現可能な相互作用ループへ変換します。

## コア ループ

1. 対象のページまたはアプリインスタンスを選択する。
2. 古いコンソールノイズを消去する。
3. BEFORE 状態をキャプチャする。
4. UI の経路を実行する。
5. 相互作用中のランタイムイベントを観察する。
6. AFTER 状態をキャプチャする。
7. 修正を適用し、必要ならアプリを再起動する。
8. ジャーニーがきれいになるまで、有効性検証を再実行する。

## 必要な入力

- 安定した起動コマンド
- 再現可能な UI ジャーニー
- DOM、コンソール、またはスクリーンショットをスナップショットできる手段
- 「きれい」の基準となるルール

## 実行手順

1. アクティブな実行計画(execution plan)に対象のジャーニーを記録する。
2. 成功を観測可能な項目として定義する: テキストの存在、ボタンの有効化、エラーの解消、コンソールの正常化、リクエスト成功。
3. 相互作用の前に初期状態をスナップショットする。
4. 一度にちょうど 1 つの経路だけを実行する。
5. ランタイムイベント、DOM 変化、可視出力を記録する。
6. ジャーニーが失敗したら、最小の責任範囲の層を修正して再起動する。
7. 同じ経路を再実行し、BEFORE/AFTER の証拠を比較する。

## きれいさの基準

- 意図した可視状態が存在する
- 予期しないエラーがない
- コンソールノイズが理解可能であるか、除去されている
- 同じ経路を再実行しても同じ結果になる

## 更新すべきリポジトリ成果物

- アクティブな実行計画
- `docs/RELIABILITY.md` — そのジャーニーがゴールデンパス(golden path)になる場合
- 可視的な動作が変わった場合は製品仕様(product spec)
