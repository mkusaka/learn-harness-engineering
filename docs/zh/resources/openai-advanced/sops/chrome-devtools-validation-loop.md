# SOP: Chrome DevTools 検証ループ

UI の変更を、コードを読むだけでなく、実際の操作、スクリーンショット、DOM 状態、console 出力で判断しなければならない場合は、この SOP を使います。

## 目的

UI 検証を、agent が繰り返し実行できる操作ループに変え、このユーザージャーニーがきれいになるまで回し続けます。

## コアとなるループ

1. 対象のページまたは app インスタンスを選定する。
2. 既存の console ノイズを消す。
3. BEFORE 状態を記録する。
4. UI のパスを発火させる。
5. 操作中の runtime events を観察する。
6. AFTER 状態を記録する。
7. 問題を修正し、必要なら app を再起動する。
8. 同じ検証を何度も再実行し、その旅程が clean になるまで続ける。

## 必須入力

- 安定した起動コマンド
- 再現可能な UI journey
- DOM、console、またはスクリーンショットを取得する手段
- 「何をもって clean とするか」の明確な基準

## 実行 SOP

1. 対象の旅程を active plan に書き込む。
2. 観測可能な挙動で成功を定義する。たとえば、テキストが表示される、ボタンが押せる、エラーが消える、console がきれいになる、リクエストが成功する、など。
3. 操作前に初期状態を撮る。
4. 一度に発火させるのは 1 つのパスだけにする。
5. runtime event、DOM の変化、可視出力を記録する。
6. 失敗した場合は、最小責任層だけを修正し、その後再起動する。
7. 同じパスを再実行し、BEFORE/AFTER の証拠を比較する。

## Clean 基準

- 期待する可視状態が表示されている
- 想定外のエラーがない
- console ノイズが理解済み、または解消済みである
- 同じパスを再実行しても結果が一致する

## 同期して更新すべきリポジトリ成果物

- 現在の active execution plan
- これが黄金旅程になった場合は `docs/RELIABILITY.md` を更新する
- 可視挙動が変わった場合は product spec を更新する
