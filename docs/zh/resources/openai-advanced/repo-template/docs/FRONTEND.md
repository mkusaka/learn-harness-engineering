# FRONTEND.md

このファイルは、安定したフロントエンドの期待値を定義し、agent が毎回その場で UI パターンを考案するのを避けるためのものです。

## UI の原則

- まずは分かりやすさを確保し、そのうえで新しさを追求します。
- 交互の流れは、見つけやすく、やり直せて、再開しやすいこと。
- 一回限りの変種をあちこちに増やすより、少数の再利用可能なコンポーネントとして整理します。
- アクセシビリティの確認は通常の検証の一部であり、最後の仕上げ作業ではありません。

## ガードレール

- デザインシステムやコンポーネントライブラリの参考資料は `docs/references/` に置きます。
- 重要なユーザー状態は明示的に記録します: `empty`、`loading`、`success`、`error`、`retry`。
- 異なるフローでも、文言、キーボード操作、視覚的な階層を一貫させます。
- UI バグを修正したら、対応する検証手順もあわせて追加します。

## 検証要件

- 重要なユーザージャーニーについては証跡を残します。
- ブラウザまたはランタイムでの検証手順を、関連する plan に書き込みます。
- ビジュアルリグレッションが起こりやすい場合は、スクリーンショットか DOM チェックを標準化します。
