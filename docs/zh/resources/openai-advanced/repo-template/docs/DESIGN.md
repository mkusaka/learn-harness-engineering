# DESIGN.md

このファイルは設計ドキュメントの入口です。簡潔に保ち、より詳細な内容は
`docs/design-docs/` 内の個別ファイルに振り分けてください。

## 目的

単発のチャット、1 回の sprint、1 人の reviewer の記憶を超えて残るべき、製品およびシステム設計上の決定を記録します。

## 先に確認する場面

- 現在の設計思想を理解したいとき
- 新しいパターンを導入しようとしているとき
- どの設計が確定済みで、どれが未確定かを判断したいとき

## 中核となる設計ドキュメント

- `docs/design-docs/index.md`：accepted / proposed / deprecated の文書インデックス
- `docs/design-docs/core-beliefs.md`：プロジェクト全体の agent-first の中核となる信念

## 設計ルール

- 設計ドキュメントは小さく、新しく保つ。
- 1 つの意思決定領域には、できるだけ 1 つの文書を対応させる。
- ある変更が設計ドキュメントに依存する場合は、plan と spec でその文書を明示的にリンクする。
- ある設計ルールが運用上の必須要件になったら、自動チェックに昇格させるか、`ARCHITECTURE.md` を更新する。
