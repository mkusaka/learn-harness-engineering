# PRODUCT_SENSE.md

このファイルには、コードだけでは信頼できる形で表現しきれない製品判断を記録します。

## 製品の核

- 主要ユーザー：`[替换]`
- 実現したいタスク：`[替换]`
- 最も解決したい中心的な課題：`[替换]`
- 許容できる品質基準：`[替换]`

## 製品ルール

- 機能をむやみに増やすより、ユーザーが体感できる信頼性を優先します。
- 振る舞いに曖昧さがある場合は spec の不足とみなし、勝手に解釈して許可しません。
- 実装によってユーザーが見たり信頼したりするものが変わるなら、対応する spec を更新します。
- 個別のフローは product spec に、フローをまたぐ製品上の優先順位はここに書きます。

## 禁止パターン

- 目に見えない破壊的な操作
- ユーザーのフィードバックがない静かな失敗
- ユーザーに見える状態に明確な truth source がないこと
- 一言で説明できない機能
