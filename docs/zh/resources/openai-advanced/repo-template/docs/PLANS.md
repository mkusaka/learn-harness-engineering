# PLANS.md

このファイルでは、実行計画をどのように作成し、更新し、完了させ、アーカイブするかを定義します。

## いつ plan が必要か

作業が次のいずれかに当てはまる場合は、execution plan を作成します。

- 複数の会話にまたがる
- 複数のサブシステムに同時に影響する
- 検証やリリースのリスクが小さくない
- 明示的に記録すべき未決定事項がある

## plan の置き場所

- `docs/exec-plans/active/`：現在、作業を推進している plan
- `docs/exec-plans/completed/`：完了しているが、文脈を残しておきたい plan
- `docs/exec-plans/tech-debt-tracker.md`：先送りにした技術的負債と follow-up

## 最低限含めるべき項目

- 目的
- 範囲と、明確にやらないこと
- 検証手順
- リスクと blocker
- 進捗ログ
- 未決定事項

## 運用ルール

- active plan は、同時点で明確な現在のステップを 1 つだけ持つこと。
- plan は作業の進行に合わせて更新し、静的な文章として扱わないこと。
- ある決定によって実装方針が変わったら、その内容を plan に記録すること。
- 完了した plan は `completed/` に移し、後続の agent が履歴の文脈を見つけられるようにすること。
