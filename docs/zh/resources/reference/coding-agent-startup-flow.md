# コーディングエージェントの起動フロー

初期化が完了したら、各コーディングセッションはこのフローで始めます。

## 固定の起動テンプレート

1. `pwd` を実行して、リポジトリのルートディレクトリを確認する
2. `claude-progress.md` を読む
3. `feature_list.json` を読む
4. `git log --oneline -5` で直近のコミットを見る
5. `./init.sh` を実行する
6. 基本的な smoke test か end-to-end の経路を1つ実行する
7. ベースの状態が壊れている場合は、先にそれを修正する
8. 最優先の未完了機能を選ぶ
9. その機能だけに集中し、検証されるか、明確に blocked になるまで作業する

## なぜ順序を崩してはいけないのか

- `pwd` により、誤ったディレクトリで作業するのを防げる
- progress と feature のファイルを先に読むことで、永続化された状態を取り戻せる
- 最近のコミットを見ると、直前に何が起きたかを把握できる
- `init.sh` により、起動手順を記憶頼みではなく標準化できる
- 基本検証を先に実行すれば、壊れた状態の上に変更を重ねずに済む

## 対応するクローズ手順

同じセッションを終えるときも、これらを対応する形で行います。

1. 進捗を記録する
2. 機能の状態を更新する
3. 必要に応じて引き継ぎ要約を書く
4. 安全な状態のコードをコミットする
5. そのまま再開できるきれいな環境を残す
