# 方法対応表

この表は、長時間稼働する coding-agent でよく起きる失敗パターンを、最初に補うべき成果物やルールに対応づけたものです。

| 失敗パターン | 実際の症状 | 最優先の修正 | 主な成果物 |
| --- | --- | --- | --- |
| コールドスタートの混乱 | 新しいセッションで状態や起動方法を毎回手探りし直す | リポジトリを唯一の事実源にする | `claude-progress.md` |
| スコープの肥大化 | 一度に複数の機能を始めて、どれもきちんと終わらない | 現在のアクティブ範囲を制限する | `feature_list.json` |
| 完了の早宣言 | コードを変更しただけで「完了」と言うが、実行可能な証拠がない | 完了を検証証拠に結び付ける | `clean-state-checklist.md` |
| 起動の脆さ | セッションのたびに、プロジェクトの起動方法を学び直す必要がある | 起動と検証の手順を統一する | `init.sh` |
| 引き継ぎの弱さ | 次のラウンドで、何が使えて何が壊れていて次に何をすべきかが分からない | 引き継ぎ要約を明確に書く | `session-handoff.md` |
| レビューの主観化 | 品質判断が個人の記憶や感覚に依存する | 固定した観点で採点する | `evaluator-rubric.md` |

## 使用原則

まずは、現在の失敗パターンを最も直接的に取り除ける成果物を優先して補ってください。問題が起きるたびに、長すぎる instruction ファイルへさらにルールを積み増ししないでください。
