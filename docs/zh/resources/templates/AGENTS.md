# AGENTS.md

このリポジトリは、長時間稼働する coding agent のワークフローを想定しています。目的は、できるだけ速くコードを出すことではなく、各会話が終わった後でも、次の会話が推測なしでそのまま作業を続けられる状態を保つことです。

## 開始手順

コードを書く前に、次のことを行ってください。

1. `pwd` で現在のディレクトリを確認する。
2. `claude-progress.md` を読み、最新の検証済み状態と次の手順を把握する。
3. `feature_list.json` を読み、優先度が最も高い未完了機能を選ぶ。
4. `git log --oneline -5` で最近のコミットを確認する。
5. `./init.sh` を実行する。
6. 新しい機能を始める前に、必須の smoke test か end-to-end 検証を先に実行する。

基礎的な検証が最初から失敗する場合は、先に土台を修復してください。壊れた開始点のまま新しい機能を積み重ねてはいけません。

## 作業ルール

- 一度に 1 つの機能だけを扱う。
- 「コードを書いたから」という理由だけで機能完了にしない。
- 現在の blocker を解消するための狭い範囲の修正を除き、他の機能に作業を広げない。
- 実装中に検証ルールを密かに弱めない。
- 会話ログよりも、リポジトリ内の永続化されたファイルを優先して参照する。

## 必須ファイル

- `feature_list.json`：機能状態の唯一の正本
- `claude-progress.md`：会話の進捗と、現在の検証済み状態
- `init.sh`：起動と検証の共通エントリポイント
- `session-handoff.md`：長い会話向けの任意の引き継ぎ要約

## 完了条件

機能は、次の条件をすべて満たしたときだけ完了とみなします。

- 目標の動作が実装されている
- 要求された検証を実際に実行済みである
- 証拠が `feature_list.json` か `claude-progress.md` に記録されている
- リポジトリが標準の起動手順で再び作業を開始できる状態である

## 終了時の処理

会話を終える前に、次を実施してください。

1. `claude-progress.md` を更新する
2. `feature_list.json` を更新する
3. 未解決の risk や blocker を記録する
4. 作業が安全な状態になったら、明確なコミットメッセージで commit する
5. 次回の会話で `./init.sh` をそのまま実行できることを保証する
