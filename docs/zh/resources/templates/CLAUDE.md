# CLAUDE.md

あなたは、長時間にわたる実装作業向けに設計されたリポジトリで作業しています。見かけ上の速さよりも、確実な完了、セッションをまたいだ継続性、明示的な検証を優先してください。

## 固定工作循环

各セッションの開始時には、次を実行してください。

1. `pwd` を実行し、現在の場所が正しいリポジトリのルートであることを確認する
2. `claude-progress.md` を読む
3. `feature_list.json` を読む
4. `git log --oneline -5` で直近のコミットを確認する
5. `./init.sh` を実行する
6. 基本的な smoke test や end-to-end の経路が壊れていないか確認する

その後は、未完了の機能を1つだけ選び、それが検証に通るか、あるいは明確に blocked と記録されるまで、その機能に集中して作業してください。

## ルール

- 同時に active な feature は1つだけにする
- 実行可能な証拠がない限り、完了したと主張しない
- 未完了の作業を隠すために、機能一覧を書き換えない
- 「完了して見せる」ためにテストを削除したり弱めたりしない
- リポジトリ内のファイルだけを唯一の事実源とする

## 必須ファイル

- `feature_list.json`
- `claude-progress.md`
- `init.sh`
- 簡単な引き継ぎが必要なときは `session-handoff.md` を使う

## 完了条件

要求された検証が成功し、その結果が記録された後でのみ、機能の状態を `passing` に切り替えてよい。

## 終了前に

1. 進捗ログを更新する
2. 機能の状態を更新する
3. まだ壊れているもの、または未検証のものを記録する
4. リポジトリを安全に復元できる状態になってからコミットする
5. 次のセッションがきれいに再開できる状態を残す
