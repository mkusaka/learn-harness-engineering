# プロジェクト 03: 範囲制御と根拠に基づく検証

明示的な範囲（scope）制御と検証（verification）ゲートが、実装の正確性を向上させるかを評価します。

エージェントには、複数の機能を同時に実装しようとする傾向があります。これを範囲逸脱（scope drift）と呼びます。このプロジェクトでは、「一度に1つの機能」という戦略を明示的に適用したとき、成果物の品質がどのように変わるかを測定します。

## ディレクトリ説明

| ディレクトリ | 意味 |
|----------|------|
| `starter/` | **出発点** — P2 の解答（solution）をベースにしており、文書のチャンク化（chunking）、メタデータ抽出、インデックス状態、基本的なQ&A機能は未実装です。「一度に1つの機能」戦略の制約はありません。 |
| `solution/` | **参考実装** — すべての機能が実装済みで、AGENTS.md には「一度に1つの機能」戦略が含まれています。また、feature_list.json には失敗から成功への切り替え過程と検証の証拠が示されています。 |

## 使用方法

```sh
cd starter
npm install
# エージェントが複数の機能を同時に実装しようとするかを観察します（範囲逸脱）

cd ../solution
npm install
# 範囲制御を適用して再実行し、機能実装の正確性を比較します
```

## このプロジェクトで扱う機能

- 文書のチャンク化（段落を認識、約500文字）
- メタデータ抽出（単語数、行数、段落数）
- インデックス状態のUI表示
- 出典引用（citation）を含む基本的なQ&Aフロー
