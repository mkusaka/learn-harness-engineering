# Retrieval Plan

## Overview

この文書では、ナレッジベースアプリケーションでテキスト検索を実装するための戦略をまとめます。目的は、外部の LLM API を使わずに、取り込んだ文書に基づく根拠のある質問応答を実現することです。

## Chunking Approach

文書は、段落を考慮したアルゴリズムでチャンクに分割します。
- 2つの改行で分割する（段落の境界）
- 短い段落は、チャンクが約 500 文字になるまで結合する
- 各チャンクに一意の ID、文書参照、メタデータを付与する

## Keyword Matching

検索システムでは、キーワードベースの照合を使用します。
1. 質問を個々の単語に分割する
2. ストップワード（3文字未満の単語）を除外する
3. 各チャンクについて、質問のキーワードが内容にいくつ含まれるかを数える
4. キーワードの重なりスコアに基づいてチャンクを順位付けする
5. 最も関連性の高い上位 2 件のチャンクを引用として返す

## Citation Format

各引用には次の情報を含めます。
- 文書 ID とタイトル
- 文書内でのチャンクのインデックス
- テキストの抜粋（チャンクの先頭 200 文字）

## Mock Q&A Patterns

モック Q&A サービスには、よくあるトピック向けのあらかじめ定義された回答パターンが含まれています。
- アーキテクチャと設計に関する質問
- 文書の取り込みと管理
- インデックス作成と検索
- 議事録と要約

どのパターンにも一致しない質問には、最も関連性の高い引用に基づく汎用的な応答を返すか、インデックス化された文書がないことを示します。

## Confidence Scoring

応答には信頼度スコアを含めます。
- 引用が見つかった場合は 0.85
- 引用がない場合は 0.30

このスコアリングにより、UI 上で根拠のある回答と推測的な回答を視覚的に区別できます。
