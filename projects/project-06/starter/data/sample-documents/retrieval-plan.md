# Retrieval Plan

## Overview

この文書では、ナレッジベースアプリケーションにおけるテキスト検索機能の実装方針を示します。目的は、外部の LLM API を使わずに、取り込んだ文書に対して根拠に基づく質問応答を可能にすることです。

## Chunking Approach

文書は、段落を考慮したアルゴリズムでチャンクに分割します。
- 2 つの改行で区切る（段落の境界）
- 短い段落は、チャンクが約 500 文字になるまで結合する
- 各チャンクに一意の ID、文書参照、メタデータを付与する

## Keyword Matching

検索システムは、キーワードベースのマッチングを使用します。
1. 質問を個々の単語に分割する
2. ストップワード（3 文字未満の単語）を除外する
3. 各チャンクについて、質問のキーワードが本文中にいくつ含まれるかを数える
4. キーワードの重なりスコアに基づいてチャンクを順位付けする
5. 最も関連性の高い上位 2 件のチャンクを引用として返す

## Citation Format

各引用には次の情報を含めます。
- 文書 ID とタイトル
- 文書内でのチャンクのインデックス
- テキストの抜粋（チャンクの先頭 200 文字）

## Mock Q&A Patterns

モック Q&A サービスには、よくあるトピック向けの事前定義済み回答パターンが含まれます。
- アーキテクチャと設計に関する質問
- 文書の取り込みと管理
- インデックス作成と検索
- 会議メモと要約
- ロギングと可観測性
- フィードバックと品質

どのパターンにも一致しない質問については、システムは最も関連性の高い引用に基づく汎用的な応答を返すか、インデックス済みの文書がないことを示します。

## Confidence Scoring

応答には信頼度スコアを含めます。
- 引用が見つかった場合は 0.85
- 引用が利用できない場合は 0.30

このスコアリングにより、UI 上で根拠のある回答と推測的な回答を視覚的に区別できます。

## Benchmarking

検索パイプラインは、次の指標でベンチマークを取るべきです。
- 文書取り込みスループット（ファイル/秒）
- インデックス作成速度（チャンク/秒）
- クエリ遅延（質問 1 件あたりのミリ秒）
- 引用の正確性（返されたチャンクの関連性）
