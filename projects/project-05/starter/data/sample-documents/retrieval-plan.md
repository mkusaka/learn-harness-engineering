# Retrieval Plan

## Overview

この文書では、ナレッジベースアプリケーションでテキスト検索を実装するための戦略を示します。目的は、外部の LLM API を使わずに、取り込んだ文書に対して根拠に基づく質問応答を可能にすることです。

## Chunking Approach

文書は、段落を考慮したアルゴリズムでチャンクに分割されます。
- 2 つの改行（段落の区切り）で分割する
- チャンクが約 500 文字になるまで短い段落を結合する
- 各チャンクに一意の ID、文書参照、メタデータを付与する

## Keyword Matching

検索システムは、キーワードベースの照合を使用します。
1. 質問を個々の単語に分割する
2. ストップワード（3 文字未満の単語）を除外する
3. 各チャンクについて、質問のキーワードがコンテンツ内にいくつ含まれているかを数える
4. キーワードの一致スコアでチャンクを順位付けする
5. 最も関連性の高い上位 2 件のチャンクを引用として返す

## Citation Format

各引用には次の情報が含まれます。
- 文書 ID とタイトル
- 文書内でのチャンクのインデックス
- テキストの抜粋（チャンクの先頭 200 文字）

## Mock Q&A Patterns

モック Q&A サービスには、よくあるトピック向けの事前定義済み回答パターンが含まれています。
- アーキテクチャと設計に関する質問
- 文書の取り込みと管理
- インデックス作成と検索
- 会議メモと要約

どのパターンにも一致しない質問については、システムは最も関連性の高い引用に基づく一般的な応答を返すか、インデックス済みの文書がないことを示します。

## Confidence Scoring

応答には信頼度スコアが含まれます。
- 引用が見つかった場合は 0.85
- 引用が利用できない場合は 0.30

このスコアリングにより、UI で根拠の明確な回答と推測に基づく回答を視覚的に区別できます。
