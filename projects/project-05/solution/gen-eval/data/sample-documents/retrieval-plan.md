# 検索計画

## 概要

この文書では、ナレッジベースアプリケーションでテキスト検索を実装するための方針を説明します。外部の LLM API を使わずに、取り込んだ文書に対して根拠に基づく質問応答を可能にすることが目的です。

## チャンク化の方針

文書は、段落を考慮したアルゴリズムでチャンクに分割します。
- 2つの改行（段落境界）で分割する
- チャンクが約 500 文字に達するまで短い段落を結合する
- 各チャンクに一意の ID、文書参照、メタデータを付与する

## キーワード一致

検索システムは、キーワードベースの一致を使います。
1. 質問を個々の単語に分割する
2. ストップワード（3 文字未満の語）を除外する
3. 各チャンクについて、質問のキーワードが内容にいくつ含まれるかを数える
4. キーワードの重なりスコアでチャンクを順位付けする
5. 最も関連性の高い上位 2 件のチャンクを引用として返す

## 引用形式

各引用には次の情報を含めます。
- 文書 ID とタイトル
- 文書内のチャンク番号
- テキストの抜粋（チャンクの先頭 200 文字）

## モック Q&A パターン

モック Q&A サービスには、よくあるトピック向けの定義済み回答パターンが含まれます。
- アーキテクチャと設計に関する質問
- 文書の取り込みと管理
- インデックス作成と検索
- 議事録と要約

いずれのパターンにも一致しない質問については、最も関連性の高い引用に基づく一般的な応答を返すか、索引化された文書がないことを示します。

## 信頼度スコア

応答には信頼度スコアが含まれます。
- 引用が見つかった場合は 0.85
- 引用が利用できない場合は 0.30

このスコアリングにより、UI 上で根拠のある回答と推測に基づく回答を視覚的に区別できます。
