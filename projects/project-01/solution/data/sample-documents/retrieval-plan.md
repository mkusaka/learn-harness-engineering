# Retrieval Plan

## Overview

この文書では、ナレッジベースアプリケーションにおけるテキスト検索の実装方針をまとめます。目的は、外部の LLM API を使わずに、取り込んだドキュメントに対して根拠のある質問応答を実現することです。

## Chunking Approach

ドキュメントは、段落を考慮したアルゴリズムでチャンクに分割します。
- 改行2つで区切る（段落の境界）
- 短い段落は、チャンクが約500文字に達するまで結合する
- 各チャンクには、一意の ID、ドキュメント参照、メタデータを付与する

## Keyword Matching

検索システムは、キーワードベースのマッチングを使用します。
1. 質問を個々の単語に分割する
2. ストップワード（3文字未満の単語）を除外する
3. 各チャンクについて、質問のキーワードが内容にどれだけ含まれているかを数える
4. キーワードの重なりスコアでチャンクを順位付けする
5. 最も関連性の高い上位2件のチャンクを引用として返す

## Citation Format

各引用には次の情報を含めます。
- ドキュメント ID とタイトル
- ドキュメント内でのチャンクのインデックス
- テキストの抜粋（チャンクの先頭200文字）

## Mock Q&A Patterns

モック Q&A サービスには、よくある話題向けの定義済み回答パターンが含まれています。
- アーキテクチャと設計に関する質問
- ドキュメントの取り込みと管理
- インデックス作成と検索
- 会議メモと要約

どのパターンにも一致しない質問については、システムは最も関連性の高い引用に基づく汎用的な応答を返すか、インデックス済みのドキュメントがないことを示します。

## Confidence Scoring

応答には信頼度スコアを含めます。
- 引用が見つかった場合は 0.85
- 引用が利用できない場合は 0.30

このスコアリングにより、UI 上で根拠のある回答と推測に基づく回答を視覚的に区別できます。
