# プロジェクト 01: ベースライン対ミニマルハーネス

弱いハーネス(harness)（プロンプトだけに依存するもの）と、明示的なハーネス（ルールファイル + 検証(verification)メカニズム）が、AI コーディングエージェントの作業完了率に与える影響を比較します。

このプロジェクトは本講義の出発点です。ハーネスの有無による違いを、実際に見て確認することが目的です。同じ作業を2つの条件で実行し、結果を測定してください。

## ディレクトリ説明

| ディレクトリ | 意味 |
|----------|------|
| `starter/` | **開始点** — 曖昧な `task-prompt.md` が1つあるだけで、AGENTS.md と feature_list.json はありません。エージェントに渡す「弱いハーネス」版です。 |
| `solution/` | **参考実装** — 同じアプリコードですが、完全なハーネスファイル（AGENTS.md, feature_list.json, init.sh, claude-progress.md）を備えています。「明示的なハーネス」版です。 |

## 使い方

```sh
# 1. starter(弱いハーネス)でエージェントの作業を1回実行
cd starter
npm install
# task-prompt.md の内容を Claude Code / Codex にプロンプトとして渡す
# エージェントがウィンドウの起動、文書一覧、質疑応答パネル、データディレクトリの完了を試みるようにする

# 2. solution(明示的なハーネス)でもう1回実行
cd ../solution
npm install
# エージェントが AGENTS.md を読み、規則に従って同じ作業を行うようにする

# 3. 2つの結果を比較
# - 作業は完了したか?
# - 何回再試行が必要だったか?
# - エージェントが早い段階で「完了」と宣言したか?
```

## このプロジェクトで扱う機能

- Electron ウィンドウの起動に成功する
- UI に文書一覧エリアを表示する
- UI に質疑応答パネルを表示する
- アプリがローカルデータディレクトリを生成して使用する
