# プロジェクト 04: ランタイムの可観測性と構造的制御

ランタイムの可観測性(observability)と構造化された境界チェックを導入しながら、仕込まれたランタイム欠陥をデバッグします。

可観測性とは、エージェントの実行中に何が起きているかを確認できる能力です。構造化ログとアーキテクチャ境界チェックがなければ、エージェントがバグを見つけたときに原因を特定するまでに、はるかに多くの時間がかかります。このプロジェクトでは、その差を測定します。

## ディレクトリの説明

| ディレクトリ | 意味 |
|----------|------|
| `starter/` | **開始地点** — P3 の解答(solution)を基にしており、ログと構造化された境界機能は未実装です。`IndexingService` に隠れたバグが仕込まれています。1000 文字を超えるファイルで空のチャンク(chunk)が生成されます。アーキテクチャ検査スクリプトはありません。 |
| `solution/` | **参考実装** — 構造化ログモジュール、アーキテクチャ境界検査スクリプト、そして仕込まれていたバグの修正が含まれています。 |

## 使用方法

```sh
cd starter
npm install
# 1. エージェントがログを通じてバグを見つけられるか観察する
# 2. 大きなファイルを取り込み、チャンク分割の結果が不正か確認する

cd ../solution
npm install
# 比較: 構造化ログがどのように問題の診断を加速するか
```

## このプロジェクトで扱う機能

- 起動ログ
- 取得およびインデックス作成のログ
- UI で見える QA 失敗経路
- main / preload / renderer / services レイヤーの明示的な境界
- 仕込まれたランタイム欠陥のデバッグ
