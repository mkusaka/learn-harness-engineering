# プロジェクト 02: エージェント可読なワークスペース

リポジトリ(repository) の可読性と、明示的な継続性(continuity) を示す成果物が、セッションをまたぐ開発でコンテキスト(context) の損失をどのように減らすかを示します。

新しいセッションを始めたエージェントが最初に行うのは、リポジトリを読むことです。リポジトリがエージェント向けに整えられていないと、エージェントは前回のセッションで何が起きたのかを把握するために多くの時間を費やします。このプロジェクトでは、その差を直接測定します。

## ディレクトリの説明

| ディレクトリ | 意味 |
|----------|------|
| `starter/` | **開始点** — P1 の解答(solution) をベースにしたコードで、ドキュメントの取り込み(import)、詳細表示、永続化(persistence) 機能は未実装です。ハーネスも簡素です。AGENTS.md は簡素で、session-handoff(session-handoff) がありません。 |
| `solution/` | **参考実装** — すべての新機能が実装済みで、完全なワークスペース文書(ARCHITECTURE.md, PRODUCT.md, session-handoff.md) を備えています。 |

## 使い方

```sh
# 完了するには少なくとも 2 つのエージェントセッションが必要です
cd starter
npm install
# セッション A: ドキュメント取り込みと詳細表示を実装
# セッション B: 永続化を実装（エージェントがコンテキストを素早く復元できるか観察）

cd ../solution
npm install
# 完全なハーネスで再実行し、セッション復元速度を比較
```

## このプロジェクトで扱う機能

- ドキュメント取り込みフロー（ファイル選択 + IPC 転送）
- ドキュメント詳細表示（メタデータ + 内容表示）
- 基本的な永続化（取り込んだドキュメントが再起動後も保持される）
